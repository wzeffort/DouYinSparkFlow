# 管理员健康中心与用户目录设计

## 目标

在不授予 Web 容器主机控制权的前提下，为管理员提供独立的系统健康页面；将用户管理从综合后台拆成每页 8 个的独立目录；把邮件通知管理作为综合后台的运维入口；移除综合后台的“最近执行”模块，完整执行历史仍保留在 `/runs`。

## 信息架构

- `/admin`：运维总览、健康摘要、默认额度、邀请码、定时任务、邮件通知管理入口。
- `/admin/users`：用户创建、搜索、状态管理、删除和额度入口，每页 8 个。
- `/admin/health`：主机资源、流量、服务状态、业务健康和告警，只允许管理员访问。
- `/admin/notifications`：继续承担邮件事件明细和重试；从 `/admin` 的邮件运维模块进入。
- `/runs`：保留完整执行历史；`/admin` 不再重复展示最近 20 条。

## 健康采集边界

主机上的 root-owned systemd oneshot 每分钟运行 `ops/spark_health_collector.py`。采集器只读取 `/proc`、`/sys/class/net`、根磁盘、vnStat 和固定白名单容器的状态，将无敏感信息的快照原子写入 `runtime/host-health.json`。Web 仅通过只读 bind mount 读取快照，不挂载 Docker Socket，不执行主机命令。

快照包含：采集时间、CPU、内存、根磁盘、当前上下行速率、今日/本月收发流量、固定服务状态、24 小时/7 天趋势和分级告警。历史最多保留 7 天、每 5 分钟一个采样点。快照超过 3 分钟未更新时，页面显示“采集暂时中断”，不把旧数据伪装成实时状态。

## 页面表现

健康页顶部使用五段“健康脉冲带”：网站访问、任务执行器、抖音账号、服务器资源、邮件通知。状态色使用现有珊瑚红、琥珀、青绿和深蓝灰；资源数字使用等宽数字字体，正文延续现有中文字体栈。

页面依次展示：需要处理的问题、CPU/内存/磁盘、流量趋势、服务矩阵、业务健康。磁盘阈值为 75% 提醒、85% 警告、92% 或剩余不足 2GiB 严重。第一版不提供网页端“一键清理”，只给出安全建议。

移动端保持顶部菜单和抽屉导航；资源卡单列，脉冲带可横向滚动但不得隐藏标签。所有状态不仅依赖颜色，还必须有文字和图标。

## 安全与隐私

- 健康路由、用户目录及其 JSON 接口必须管理员鉴权。
- 快照不包含 Cookie、邮箱、用户内容、完整外网 IP、环境变量或文件路径。
- 容器状态只允许固定服务名，不接受用户传入容器名。
- 主机采集脚本和 systemd 单元由 root 拥有，输出目录对 Web 只读。
- 邮件模块只显示聚合状态和进入明细页的链接。

## 验收

- 普通用户访问 `/admin/users` 和 `/admin/health` 得到 404，与现有管理员路由隐藏策略一致。
- 用户目录每页恰好 8 个，并保留额度、停用和删除操作。
- `/admin` 不出现用户列表和最近执行列表，出现邮件通知管理模块。
- 有效快照能渲染资源、流量和服务；缺失或过期快照给出明确降级提示。
- 采集器原子写入、历史有界且输出不含敏感字段。
- 全量测试通过，生产部署后 Web/Worker/Auth/Notifier 和 BPS 容器保持健康。
