# DouYinSparkFlow 邮箱与通知中心设计

**日期：** 2026-09-01\
**状态：** 待用户最终审阅\
**适用范围：** 多用户 Web 控制台、注册流程、抖音账号状态、管理员后台与独立通知发送器

## 1. 目标

为 DouYinSparkFlow 增加可靠的邮箱管理与异常通知能力，使用户无需主动打开网站，也能在抖音登录凭证失效时收到一次明确提醒。同时提供站内通知、发送记录、用户偏好和管理员运维能力。

第一阶段交付：

1. 新注册用户必须验证邮箱后才能创建正式账号并消费邀请码。
2. 现有用户继续正常使用，但登录后会看到绑定邮箱提示。
3. 用户可以绑定或换绑邮箱并管理通知偏好。
4. 抖音账号明确失效时产生站内通知和单次邮件提醒，并暂停相关任务。
5. 管理员可以查看脱敏邮箱、通知队列和投递结果。

第一阶段不包含任务连续失败和额度到期邮件。这两类通知保留数据结构与偏好入口，后续启用，避免首版范围过大。

## 2. 核心原则

- Web、Auth 和任务 Worker 不直接请求 Resend，只写数据库通知事件。
- 独立 `spark-notifier` 容器负责异步投递、重试和记录结果。
- 真实 Resend API Key 只存在于被 Git 忽略的 `.env.console`，不进入源码、数据库、镜像、日志或页面。
- 邮箱密文与查询哈希使用独立的 32 字节 PII 密钥，不与 Cookie、会话或密码密钥复用。
- 验证码、邮件操作令牌和邀请码均不明文持久化。
- 登录过期必须由明确错误码触发；网络错误、好友未找到和聊天窗口未打开不得误报。
- 同一抖音账号的同一失效周期只发送一次过期邮件。
- 邮件系统故障不得阻塞现有任务执行或导致任务重复发送。

## 3. 方案选择

### 3.1 推荐方案：数据库 Outbox

业务事务写入通知事件，由独立发送器领取并投递。该方案复用现有 SQLite 与 Docker Compose，能够提供幂等、重试、审计和故障隔离，不引入新的基础设施。

### 3.2 未采用方案

- **业务进程同步发送：** 网络延迟会拖慢注册或 Worker，异常时难以可靠重试。
- **Redis/Celery 邮件队列：** 扩展能力强，但对当前规模增加了不必要的部署和维护成本。

## 4. 数据模型

### 4.1 用户邮箱字段

在 `users` 增加：

- `email_ciphertext`、`email_nonce`：加密后的规范化邮箱。
- `email_lookup_hash`：带服务端 pepper 的确定性哈希，用于唯一性查询，不用于展示。
- `email_verified_at`：验证完成时间，空值表示未验证。
- `email_updated_at`：最近绑定或换绑时间。

邮箱规范化规则：去除首尾空格，将域名与本项目支持的邮箱整体转为小写；长度上限 254；拒绝控制字符、换行和不合法地址。数据库为非空 `email_lookup_hash` 建立唯一索引。查询哈希使用独立 PII 密钥执行带用途前缀的 HMAC，邮箱密文使用带用户或请求 ID 作为 AAD 的认证加密，防止跨记录替换。

管理员与普通页面均只使用服务层返回的脱敏邮箱，例如 `20******81@qq.com`，不直接投影加密字段。

### 4.2 待注册记录

新增 `pending_registrations`：

- `id`
- `username`
- `password_hash`
- `email_ciphertext`、`email_nonce`、`email_lookup_hash`
- `invite_id`
- `verification_code_hash`
- `verification_expires_at`
- `verification_attempts`
- `send_count`
- `last_sent_at`
- `created_at`、`expires_at`

待注册记录最长保留 30 分钟。验证成功时，在一个数据库事务内再次检查用户名、邮箱和邀请码状态，创建用户、消费邀请码、创建默认额度并删除待注册记录。

待注册阶段不创建正式用户、不消费邀请码。并发验证由唯一约束和事务保证最多创建一个正式用户。

### 4.3 邮箱换绑请求

新增 `email_verification_requests`：

- `id`
- `user_id`
- `purpose`：`bind` 或 `change`
- 新邮箱密文、nonce 与查询哈希
- 验证码哈希、过期时间、尝试次数、发送次数与最后发送时间
- `created_at`、`consumed_at`

新邮箱验证成功前保留原邮箱。成功后原子替换邮箱字段并消费请求。

### 4.4 通知偏好

新增 `notification_preferences`，以 `user_id` 为主键：

- `douyin_login_expired_email`，默认开启
- `task_repeated_failure_email`，第一阶段保存但不触发
- `quota_expiring_email`，第一阶段保存但不触发
- `quota_expired_email`，第一阶段保存但不触发
- `updated_at`

站内安全通知不可关闭；偏好仅控制邮件投递。

### 4.5 站内通知

新增 `user_notifications`：

- `id`、`user_id`
- `kind`
- `title`、安全摘要
- `action_path`：仅允许本站相对路径
- `dedupe_key`
- `read_at`、`created_at`、`resolved_at`

为 `(user_id, dedupe_key)` 建立唯一约束，防止并发重复通知。

### 4.6 邮件 Outbox

新增 `notification_events`：

- `id`、`user_id`
- `kind`
- `recipient_email_ciphertext`、`recipient_email_nonce`
- `template_key`
- `template_payload_json`：仅保存模板所需的非敏感字段
- `dedupe_key`，唯一
- `status`：`pending`、`sending`、`sent`、`failed`、`cancelled`
- `attempt_count`、`next_attempt_at`
- `provider_message_id`
- `last_error_code`、脱敏错误摘要
- `claimed_at`、`sent_at`、`created_at`、`updated_at`

事件保存创建时的收件地址密文，避免用户换绑邮箱后旧安全事件被发送到新地址。模板数据不得包含 Cookie、验证码、手机号、完整抖音凭证或 Resend API Key。

### 4.7 抖音失效周期

在 `douyin_accounts` 增加：

- `invalidated_at`
- `invalid_reason_code`
- `auth_incident_id`

首次从有效状态进入明确失效状态时生成新的 `auth_incident_id`。站内通知和邮件事件以该 ID 构建去重键。重新绑定成功后清除失效状态，但保留历史通知记录。

## 5. 注册与邮箱验证流程

### 5.1 新用户注册

1. 用户提交用户名、密码、密码确认、邀请码和邮箱。
2. 服务端执行统一格式校验和速率限制，并验证邀请码可用但不消费。
3. 服务端生成 6 位验证码，只保存带 pepper 的哈希；验证码有效 10 分钟。
4. 创建或替换对应的待注册记录，并写入邮件 Outbox。
5. 用户进入验证码页面，页面显示脱敏邮箱、剩余有效时间和重发冷却。
6. 验证成功后，在单个事务中重新校验唯一性与邀请码，创建用户并消费邀请码。
7. 自动跳转登录页，不自动创建登录会话。

公开错误统一为“注册信息或验证码无效”，避免暴露用户名、邮箱和邀请码是否存在。

### 5.2 现有用户绑定邮箱

现有用户不强制中断使用。登录后首页和账号设置显示引导卡。用户输入邮箱后收到验证码，验证成功才写入用户邮箱字段。

### 5.3 换绑邮箱

已绑定用户输入新邮箱并通过当前密码校验，再验证新邮箱。验证成功前旧邮箱继续有效。换绑成功后：

- 原邮箱不再接收新事件。
- 未发送且收件地址为旧邮箱的普通通知取消。
- 已产生的账号安全事件保持历史记录，不自动改发到新邮箱。

## 6. 防滥用与安全边界

- 验证码有效期 10 分钟，最多错误 5 次。
- 重发冷却 60 秒，重发立即使旧验证码失效。
- 同时按 IP、邮箱哈希、待注册记录和登录用户限制发送频率。
- 建议默认限制：单邮箱每小时 5 次、每日 10 次；单 IP 每小时 20 次、每日 50 次。
- 验证码与令牌日志只记录事件 ID 和固定错误码。
- 所有敏感比较使用恒定时间比较。
- 邮件重新绑定链接使用随机、单次、短期令牌；数据库只保存令牌哈希。
- 邮件链接只能跳转到本站 HTTPS 地址；操作前必须登录对应用户。
- 管理员不能查看验证码、令牌、完整邮箱或 API Key，也不能直接标记邮箱为已验证。
- 邮件 HTML 对所有用户可控字段进行转义，禁止模板注入。

## 7. 抖音登录过期通知

仅当执行器返回 `cookie_invalid` 或 `login_expired` 时触发：

1. Worker 将抖音账号从有效状态转为失效并创建 `auth_incident_id`。
2. 在同一事务中暂停该账号所有启用任务。
3. 创建不可关闭的站内通知。
4. 若用户已验证邮箱且偏好开启，则创建唯一邮件事件。
5. 如果账号已经处于同一失效周期，不重复创建通知或邮件。
6. 用户重新绑定成功后，关闭对应站内通知、清除失效状态并允许未来产生新失效周期。

网络波动、好友未找到、聊天窗口未打开、发送确认超时和 Worker 临时故障均不得触发登录过期邮件。

## 8. 邮件发送器

新增 `spark_console/notifier.py` 与 Compose 服务 `spark-notifier`：

- 单实例运行，轮询到期的 `pending` 或可重试 `failed` 事件。
- 使用短事务领取事件并提交，再在事务外请求 Resend，避免长时间占用 SQLite 写锁。
- Resend 请求使用事件 ID 作为幂等键。
- 成功后保存 provider message ID 与发送时间。
- 临时错误按照 1、5、20、60 分钟重试。
- 明确永久错误或达到上限后保持 `failed`，等待管理员人工重试。
- 进程重启时回收超时的 `sending` 事件。
- 全站邮件暂停开关开启时不领取新事件。

建议资源限制：内存 192 MiB、CPU 0.25、只读文件系统、无公开端口，与现有服务共享私有网络和数据卷。

## 9. 用户界面

### 9.1 导航与首页

- 已登录用户导航栏增加通知铃铛和未读数量。
- 首页显示邮箱状态卡：未绑定、待验证或已验证。
- 抖音账号失效时显示高优先级提醒和“重新绑定”按钮。

### 9.2 账号设置

新增邮箱管理区域：

- 查看脱敏邮箱与验证时间。
- 绑定、换绑、重新发送验证码。
- 管理邮件通知偏好。
- 显示发送冷却和固定错误信息。

### 9.3 通知中心

- 每页 6 条。
- 支持未读筛选、标记已读和跳转到相关站内页面。
- 翻页保留滚动位置，不跳回顶部。

## 10. 管理员后台

- 用户列表显示脱敏邮箱、验证状态和最近通知时间。
- 新增通知记录区域，每页 6 条，可按用户、类型和状态筛选。
- 管理员可以重试 `failed` 事件，不能重发 `sent` 事件。
- 展示待发送数、失败数、最近成功时间和连续失败数。
- 提供全站暂停/恢复邮件开关；暂停只停止投递，不删除事件。
- 页面和导出内容不包含完整邮箱、验证码、令牌和 Resend 响应正文。

## 11. 数据迁移与兼容性

- 使用现有幂等迁移机制添加字段、表和索引，不删除或重建现有数据。
- 部署迁移前调用现有数据库备份命令。
- 现有用户邮箱为空，登录与任务不受影响。
- 新注册流程在功能启用后强制邮箱验证。
- 待注册、已消费验证码和过期操作令牌按保留策略清理。
- 已发送通知保留用于审计；模板载荷按期限裁剪，防止数据库无限增长。

## 12. 配置

`.env.console.example` 只声明变量名与非敏感默认值：

- `RESEND_API_KEY=`
- `RESEND_FROM=DouYinSparkFlow <notify@oilu.cn>`
- `SPARK_PUBLIC_BASE_URL=https://wangze.oilu.cn`
- `SPARK_EMAIL_ENABLED=true`
- `SPARK_EMAIL_POLL_SECONDS=10`
- `SPARK_PII_KEY_FILE=/run/secrets/pii.key`

真实 Resend 密钥只写入本地和服务器的 `.env.console`。PII 密钥以 root 管理的 `0600` 二进制文件挂载到容器，只在环境文件中保存路径。应用启动和日志不得输出任何密钥值。

## 13. 部署与回滚

1. 只读预检磁盘、内存、容器、活动任务与登录会话。
2. 备份 SQLite 数据库和服务器 `.env.console`，创建独立的 32 字节 `pii.key` 并以只读方式挂载。
3. 部署代码与新镜像，但先保持邮件发送关闭。
4. 执行幂等迁移并验证现有页面、任务和账号数据。
5. 启动 `spark-notifier`，通过管理员测试通知验证投递。
6. 启用新用户邮箱验证，再开放正式流量。

回滚时先停止 `spark-notifier`，关闭注册入口，恢复原镜像与数据库备份。邮件服务故障不回滚任务 Worker；可通过全站开关单独停用邮件投递。

## 14. 测试策略

### 14.1 服务与模型

- 邮箱规范化、加密、唯一哈希和脱敏投影。
- 验证码过期、错误次数、重发失效和频率限制。
- 邀请码仅在验证成功时消费。
- 并发验证最多创建一个用户。
- 换绑成功前旧邮箱保持有效。

### 14.2 通知与发送器

- 同一失效周期只产生一个站内通知和一个邮件事件。
- 重新绑定后新的失效周期可以再次通知。
- 错误分类、重试时间、幂等键和崩溃恢复。
- 全站暂停、用户偏好与永久失败。
- 日志、审计和页面不泄露敏感信息。

### 14.3 Web 与权限

- 新注册两步流程、现有用户宽限绑定、换绑和通知偏好。
- 普通用户不能读取或操作他人的邮箱和通知。
- 管理员只能看到脱敏信息。
- 通知中心与后台记录每页 6 条，翻页保留位置。

### 14.4 部署验证

- Compose 中 `spark-notifier` 无公开端口且资源受限。
- `.env.console` 保持 Git 忽略，跟踪文件中无真实密钥。
- 完整测试套件、数据库迁移、容器健康和公网 HTTPS 页面。
- 测试邮件只发送到管理员明确授权的地址。

## 15. 完成标准

- 新用户未验证邮箱不能创建正式账号或消费邀请码。
- 现有用户不绑定邮箱仍可继续使用，但持续看到安全提示。
- 明确的抖音登录失效会暂停相关任务并产生一次站内和邮件提醒。
- 邮件发送失败可自动重试、人工重试且不会重复投递成功事件。
- 管理员和普通用户均无法通过页面、日志、数据库明文字段或 Git 获取敏感凭证。
- 邮件功能关闭或 Resend 不可用时，既有续火任务仍正常运行。
